# Ground projection source-validation hardening — 2026-10-10

**Scope:** source-verified, read-only original 22220 / FF50 capture projection. No change to renderer output or game state. Original DOS `CODE.2`: 558,689 bytes, SHA-256 `853e0a4dfcabebcfeecb975cf2a92b92eb4d94806d835ad30a0bab3e265bd314`. Original sentinel routine `32F4C` fills exactly seven DWORD fields and never updates nearest `22220`; original four materializer tails at `330E7,33278,3337F,33487` are the only verified depth-producing routes in this model.

## Why this change is necessary

The parallel original-source projection now present in `include/rloft/original_ground_source_projection.hpp` already handles signed 32-bit original depth, `32F4C` source sentinel vs materializers, original `C6D8` ray count and `C738` scale-table bound, and writes read-only F12 capture metadata. No duplicate model is needed. The original nearest `22220` replay receives only record depth, ordinary material and two provenance flags; it cannot itself validate the other five source DWORD fields. Previously a mislabeled `32F4C` slot with corrupt outer texture/material, prepass flags or cell/shading words could still produce a supposedly proven nearest depth.

The existing `OriginalGroundSourceProjectionModel::evaluate` now checks the COMPLETE original 32F4C slot before authorizing `nearest` or derived `FF50`: depth=0; outer=inner=0x93; prepass, texture column offset, cell index, shade decrement all zero. It still records the input's observed provenance counts, but returns no source-depth claim from any invalid slot. Unknown and contradictory provenance already fail closed.

The isolated `original_ground_source_projection_tests` now checks corruption of every nontrivial 32F4C field, including nonzero outer material, prepass, column offset, cell index and shade. The original final nonmutation assertions incorrectly expected an older fixture's `0x93`/negative values after a later loop reset every ray to 42/3000. These assertions are corrected to snapshot and compare the **actual current input** immediately around evaluation, while preserving the missing-C738 regression. This is a test correctness correction, not a change to source gameplay rules.

The existing capture field `ground_projection_lower_ff50` remains for compatibility; an explicit `ground_projection_lower_ff50_if_upper_unchanged` alias now makes clear that its value is **conditional**. Original `1F377` reloads mutable `FF50` after opaque `1F2B1..1F369` upper overlay callbacks. No native code yet proves those callbacks' effects, so the conditional projected lower must not be used as an authoritative DOS lower raster height. Dedicated capture and independent source-oracle assertions were extended.

**Verification boundary:** original 32F4C machine bytes and both callers have been independently audited already; the previous successful Windows full run #658 (214/214) predates all current FF50 models. Current registered tests are not Windows-built and require renewed user authorization for CI. Full original DOS pixels, IRQ/timing, upper overlay mutation and partially occluded ground remain pending; no readiness-score or pixel-parity claim.
