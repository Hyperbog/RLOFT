## What has been implemented

The normal original CODE.2 title → CODE.1 character creation → authentic 0x920-byte CHARS → Level22 party GPU session remains the authoritative new-game route. The live world window now adds:

- **F6** — create an atomic **native-only** Level22 session checkpoint.
- **F9** — restore that checkpoint in an already-running world, only if it belongs to the **same** original CHARS two-actor party and immutable original LEVELS.DAT source.
- **Continue Native Level22 Quicksave** — a separate explicit launcher button loads the checkpoint across process restarts and opens the game world directly with the **original CODE.1-generated CHARS image contained in the saved file**. It does not invent a party or route through an unimplemented original CODE.2 load-game menu handler.
- **`rloft_native.exe --resume <owned-original-install>`** — an equivalent direct native checkpoint continuation path.
- A failed load, corrupted file, wrong original game archive, invalid original cell, or different active party is rejected **before** the native camera or discovery map changes.

Quicksave output is under the current Windows user's **`%LOCALAPPDATA%\RLOFT-Native\Level22-Quicksave.rnp`**, not next to the original game, and never overwrites `CHARS`, `SAVE.DAT`, `LEV022.DAT` or `LEVELS.DAT`. Save uses a temporary file in the same directory then `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` to commit only after successful flush and close. Only one quicksave slot currently exists. The already-running graphics window and original source archive remain untouched by saving.

## Portable schema `RNATSV01`

`native_session_profile.cpp` exports a versioned, endian-defined binary native checkpoint containing the following fields in exact order:

| Field | Encoding | Contract |
|---|---|---|
| Magic | 8 bytes | `RNATSV01`; unequivocally *not* original DOS save |
| Version | little-endian u32 | 1 |
| Original world identity | 64 lower-case SHA-256 hex characters | must match source-world fingerprint generated by `NativeWorldRuntime` |
| Original CODE.1 transfer | 0x920 bytes | preserved verbatim; decoded and validated by `decode_native_party_start` |
| Map level | little-endian u32 | Level22 only in A3 |
| Camera column, row, heading, pitch | four IEEE754 binary64 little-endian scalars | finite, in-grid, original collision-passable, legal heading/pitch |
| Explored-cell byte count | little-endian u32 | exactly original grid width × height |
| Explored bytes | n bytes | only 0/1, source map dimensions, ≤32768 |
| Integrity SHA-256 | 64 lower-case hex characters | computed over **all preceding bytes**, checked before deserializing any state |

Integrity is **accidental-corruption detection**, not a MAC or user authentication. It does not prevent an attacker who can edit the native save from deliberately recomputing the checksum. No arbitrary paths stored inside the save are opened. Exact byte count and schema are checked before state use.

The portable core performs no I/O and does not write original media, game resources or executable images. The save representation keeps original game data separate from host rendering/navigation state. Notably, it does **not** yet contain a complete original CODE.2 mutable-world snapshot, NPC/event flags, inventory changes, character XP, combat state, timers or a reconstructed script VM. Those are **not** silently synthesized.

## Regression and Windows acceptance

New `native_session_profile_tests` exercises deterministic round-trip, identity/data equality, exact CHARS preservation, checksum sensitivity to revealed cells, malformed signature/version/truncation/content, wrong original source SHA, wrong party fields, invalid discovered-byte domain, camera angle/pitch, and original blocked cell rejection. Every decoding failure leaves the caller's world unchanged.

CMake integrates this into portable library `rloft_native_assets` and the Windows acceptance script requires the new CTest, bringing the expected full suite count from **40 to 41**. The Windows CI source path filters also include the codec and test.

**Windows CI status needs independent confirmation for the exact current code.** A pull-request test branch `ci/native-a3-session-profile-20261013` was created and PR **#18**, initial Windows run **#89**, tests the core persistence codec. The later **cross-process launcher resume** source landed after that particular PR was started and requires its **own exact-HEAD** Windows integration acceptance. Do not mistake earlier 40/40 green CI for confirmation of the new checkpoint UI.
