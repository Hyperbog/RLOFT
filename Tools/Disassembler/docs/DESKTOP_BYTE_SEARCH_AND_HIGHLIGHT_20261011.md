## Implemented behavior in the current branch (unbuilt)

- **Go To / Find:** Enter and the Go/Find button now invoke the
  same action in `AddressBox`. Existing `CS:IP` MZ,
  `object:0xOFFSET` LE and `file:0xOFFSET` original-file
  coordinate modes remain distinct.
- **Byte-pattern search:** Type `CD`, `CD 21`, `4604CD21` or
  `hex:46 04 CD 21`. The input is strictly validated as
  complete 2-digit hex bytes, at most 64 bytes. Repeated Enter
  finds the next match; scanning wraps when it reaches the
  original file's end. Source bytes are READ ONLY; the search
  never treats output generated by a disassembler as ground truth.
  Invalid/unsupported and absent patterns report clearly.
- **Individual original hex-byte click:** The existing Hexadecimal
  text pane remains copyable. A click on either digit of a
  true byte cell (e.g., `CD`) now selects those TWO characters,
  resolves the exact physical `file+0x...` byte address,
  highlights the selection, and displays its byte value in
  status text. Clicking prefixes, ASCII text, spaces or
  unbacked LE `??` cells never invents a source-byte selection.
  Mouse drags over more than four screen pixels preserve the
  previous text-select/copy behavior.
- **Hex-window source mapping:** The new reusable
  `HexByteNavigation` core helper maps positions in bounded
  fixed-column hex renderings to original physical offsets.
  `file+0x...` row headers resolve directly. LE
  object:virtual-offset rows require the validated LE loader's
  `ToFileOffset` mapping. Unknown or unbacked cells remain
  unmapped. This is file-coordinate inspection, not CPU
  execution evidence or an assertion that every byte is code.
- **Search and selection highlighting:** The Hex view uses a
  visible inactive-selection brush, a byte-exact physical
  address selection and a persisted source-coordinate marker
  when changing tabs. In the Disassembly grid a matching
  source-backed candidate instruction row is selected; the
  EXACT matching original-byte substring within its hex
  column is highlighted, without discarding the existing
  analysis row. In References, a recorded matching source
  or destination row is selected and scrolled into view.
  There is no fabricated reference or disassembly line for
  undecoded original bytes; when a byte search matches only
  original header/data bytes, the Hex tab is shown instead.
- **Multi-byte handling:** For same-line matches, the selected
  Hex text covers the full searched byte sequence and its
  separators. For matches crossing a displayed hex row,
  the **first exact byte** is highlighted and the status
  explicitly reports the whole pattern length. Full
  multi-line *discontinuous* byte highlighting would require
  a future richer renderer and is NOT claimed by this patch.
  In Disassembly the highlight spans the overlap with one
  actual candidate instruction only, not unknown adjacent code.
- **WPF UI boundaries:** The new code does not change the
  output exporter, stored original bytes, decoder accuracy
  status, analysis graph, SQLite format or current LE/MZ
  mapping contracts. GUI row styling adds visible selected
  addresses in Disassembly and References even when tabs
  are not active. This remains a Win-x64 DESKTOP-ONLY product;
  internal research CLI is not an end-user deliverable.
