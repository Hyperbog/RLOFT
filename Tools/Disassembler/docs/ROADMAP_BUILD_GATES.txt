DOSDIS — SOURCE DEVELOPMENT ROADMAP AND BUILD-GATE POLICY
Version: 1.1 | 2026-10-10
Canonical branch: disassembler-foundation
Source repository: https://github.com/Hyperbog/RLOFT
Original DOS game collection: DnD-Classics / MASTER

PURPOSE
-------
Advance substantial batches of game-agnostic reverse engineering work without
building Windows previews or invoking CI after every small source checkpoint.
Treat source commits, successful compilation, synthetic verification, original
byte verification, and user GUI acceptance as DIFFERENT levels of evidence.

POLICY (NORMATIVE)
------------------
1. "Continue" authorizes source editing, documentation, source-only regression
   fixtures and commits. It does NOT authorize building, running tests, GitHub
   Actions, publishing executables or modifying original game files.
2. Build, execute tests, publish a preview or run CI ONLY after the owner
   explicitly asks/approves. A roadmap gate marked READY is a request for
   authorization, NOT permission to run the gate.
3. Batch related changes (normally several coherent commits) before asking for
   Windows execution. Stop earlier only for a significant runtime/ABI/schema
   change, a safety concern, or a user request for an interactive preview.
4. Every source-only commit receives lightweight STATIC review: original-byte
   boundaries, overflow checks, null/malformed-input policy, public contracts,
   source identity, status/evidence labels, bounds, documentation, regression
   fixture creation, branch HEAD and workflow manual-only state.
   Such checks are not compilation and MUST NOT be reported as tests passed.
5. No proprietary game bytes or executable archive content in development
   commits, synthetic fixtures, published artifacts or hosted CI. Known-answer
   manifests are external comparison input only, never decoder seeds.
6. The engine remains title/filename independent. Distinguish physical file
   offsets, MZ module offsets, 16-bit segment:offset, LE object offsets and
   simulated runtime addresses. Keep all inferred execution unverified.
7. Owner-supplied original game collection is available in DnD-Classics/MASTER.
   Ask for specific original files only when real-byte validation is blocked;
   unavailable archives do not imply missing usable game files.
8. Update this roadmap as evidence changes; do not silently call an item DONE
   because source exists. Preserve rejected/unknown paths and missing coverage.
9. INDEPENDENT VALIDATION IS A MANDATORY ACCEPTANCE REQUIREMENT for the
   correctness/format portion of G2-G8 and for all first/final-release accuracy
   claims. No test written from DOSDis's own outputs counts as an outside
   correctness oracle. Use separately researched original-byte known answers,
   published format/ISA semantics, and independently implemented decoders/
   traces as appropriate; compare at the EXACT built SHA with provenance.
   Failure, missing evidence or unexplained disagreement blocks independent
   acceptance, not source editing or accurately reported build-only success.
10. Apply docs/INDEPENDENT_VALIDATION_POLICY.md as the NORMATIVE oracle,
    sampling, discrepancy, review and pass/fail contract. Use
    docs/INDEPENDENT_VALIDATION_RECORD_TEMPLATE.md for each accepted scope.
    Builds, original corpus execution and CI remain owner-authorized only.

EVIDENCE STATES
---------------
PLANNED: scoped, no source change.
IN PROGRESS: active implementation.
SOURCE COMPLETE: committed; static review only; tests not run for that batch.
COMPILED: owner-authorized Windows compile passed at the cited commit.
SYNTHETIC VERIFIED: corresponding generated regression suites executed.
ORIGINAL VERIFIED: exact-hash game source was checked and results recorded.
GUI VERIFIED: the user exercised the named UI interaction successfully.
INDEPENDENT VALIDATION PENDING: outside-oracle comparison not completed.
INDEPENDENT VERIFIED: named feature/format scope passed independently authored
  exact-source checks, mandatory negative cases, second evidence class and
  discrepancy review at the cited compiled SHA; never a whole-image claim
  unless a complete independently verified denominator exists.
BLOCKED: concrete blocker and requested input recorded.
DEFERRED: out of current release scope.

SCHEDULE / BATCH RULES
----------------------
Default: 3–8 cohesive source commits per review batch; no arbitrary calendar
deadline or promised progress %. Publish short status with completed scope,
risk, unresolved cases, last source HEAD and last BUILT HEAD.
A build gate should execute after a coherent major analyzer capability,
a new loader/parser family, a persistence schema change requiring migration,
a serious correctness/safety bug, or explicit user request. Not after
documentation, fixture-only additions or routine parser refactors.
At a ready gate, ASK for build authorization. Do not call CI implicitly.

REQUEST ORIGINAL FILES ONLY WHEN NECESSARY
------------------------------------------
Original bytes are needed for targeted G3/G4/G5/G6 checks, not for building
source-only algorithms or synthetic tests. Prefer the already accessible
DnD-Classics MASTER tree. If GitHub connector cannot transfer opaque bytes,
identify the smallest named files and precise hash/version required.
Never claim an unseen original was tested.
